## 3. Hướng B: prompt hiệu chỉnh deformable cross-attention

**Mục đích:** để prompt của từng vật điều khiển **chỗ nhìn** (offset) và **mức quan trọng của điểm nhìn** (trọng số), nhắm vào nhầm mã giữa SKU cùng nhóm hàng (41,5% của 564) và các cặp như 98/97_milk.

**Lấy từ plan Q (Q2):** tách hai luồng (offset theo vị trí, trọng số theo nội dung) **không** làm ở đây, vì nó đổi đường tính của decoder đã đóng băng, nên phải chạy lại FSA. Đưa vào "để sau" (§7). B chỉ **cộng thêm** phần hiệu chỉnh.

### 3.1 Thiết kế

```
p_q   = mean(Ek_q, Ev_q)                       # (B, Q, 256): prompt riêng của query q (từ A)
Δoff  = W_off · p_q        (256 → 256)          # khởi tạo 0
Δatt  = W_att · p_q        (256 → 128)          # khởi tạo 0
α_l   = α_max · tanh(β_l)  (α_max = 0,5, β_l khởi tạo 0, nên α = 0 lúc đầu)
offset   = Linear_off(h) + α_l · Δoff
trọng số = softmax(Linear_att(h) + α_l · Δatt)
```

Khởi tạo: `W = 0` và `β = 0`, nên lúc đầu đầu ra **giống hệt** r3_real (test B-T1). Vì α = tanh(0) = 0, gradient vào `W` cũng bằng 0 ở bước đầu. Để tránh kẹt, khởi tạo **β nhỏ khác 0** (ví dụ 0,1) và **W = 0**: đầu ra vẫn giống hệt, còn gradient vào W khác 0 (test B-T5).

## 4. Hướng C1: query đề xuất từ encoder

**Mục đích:** thêm K query bắt đầu ở **đúng chỗ encoder thấy có vật**, nhắm vào 297 vật mô hình không thấy (`miss`). Không nhắm vào 331 vật bị lọc mất (việc của C0).

**Lấy từ plan Q (Q1):** dùng lại `gen_encoder_output_proposals` và `get_proposal_pos_embed` của two-stage HF, nhưng **không** bật `config.two_stage` (F5). Không dùng cột 0 của `class_embed` làm điểm "có vật" (plan Q Task 1.3 cảnh báo luật đóng băng hàng lớp làm hỏng cột này); C1 có đầu chấm điểm riêng.

### 4.1 Thiết kế

```
memory = đầu ra encoder (lượt 1)
grid, anchors = gen_encoder_output_proposals(memory, mask, shapes)      # 1 đề xuất / vị trí (anchor)
h        = LayerNorm(Linear(grid))                                       # proposals.enc_output
score    = Linear(h) → 1                                                 # proposals.score: "có vật"
box      = anchors + MLP(h) → 4                                          # proposals.box (logit)
top-K theo score → box_K (detach)
query_pos, target = split(LayerNorm(Linear(pos_embed(box_K))))          # proposals.pos_trans: (B, K, 256) ×2
reference_K = sigmoid(box_K)[..., :2]                                     # F4: tâm box, 2 chiều
decoder nhận [300 query học được ; K query đề xuất]
```

- **Lượt 2 dùng lại đề xuất của lượt 1** (F7): `prompted_outputs` và bước train truyền `proposals` (box_K) từ lượt 1 sang lượt 2. A ghép query theo chỉ số, nên thứ tự phải giữ nguyên.
- **Loss phụ** (chỉ khi train): Hungarian **nhị phân** giữa K đề xuất và mọi vật GT: focal cho `score`, L1 + GIoU cho `box`. Dùng `matcher` và hàm loss có sẵn của DETR, lớp duy nhất là "vật". Hệ số `λ_prop` (mặc định 1).
- **Loss chính:** matching Hungarian trên 300 + K query như bình thường (hàm loss không phụ thuộc số query).
- **K mặc định 100.** Chi phí decoder tăng khoảng 33%, mà decoder chỉ chiếm khoảng 2% thời gian suy luận (số đo `p1_check` trên r4: decoder 0,17 giây so với 4,5 giây).
